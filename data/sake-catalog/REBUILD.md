# sakeだけを空にして2,296商品を入れ直す

対象：MariaDB 10.11。MariaDB 10.11.19で検証。通常の追加SQLとは別の、今回の再構築依頼用です。

**現在の `sake` 全行と、そこに紐づくお気に入り・レビュー・商品タグ・詳細JSONを削除します。IDも1から振り直します。** 会員、既存の酒蔵・酒種・タグマスタ、投稿、診断履歴は削除しません。不足する酒蔵・酒種だけを追加します。

## インポート

1. 対象DBをバックアップし、実行中はアプリの登録・投稿操作を停止します。
2. phpMyAdminで既存のアプリDBを選択します。
3. [再構築SQL](../sake_catalog_rebuild.sql) または [ZIP版](import/sake_rebuild_2296.sql.zip) を保存します。ZIPは解凍します。
4. 「インポート」でSQLファイル全体を選び、UTF-8・SQL形式で実行します。外部キーのチェックは有効にします。
5. 最後に `status = rebuilt`、`inserted_products = 2296`、`first_id = 1`、`last_id = 2296` と、以下の列順を確認します。

```text
id
brewery_id
sake_type_id
name
region
abv
price
image_url
description
created_at
```

SQLは `USE` を含めないため、選択したDBに適用されます。MariaDBの匿名複合文 `BEGIN NOT ATOMIC` と `DELIMITER` を使用します。MySQLへこの再構築版を実行しないでください。通常の追加版・属性補完版は引き続き両DB向けです。

## 旧版でphpMyAdminの #2014 が出た場合

旧版は再登録をCOMMITした後、匿名複合文から複数の結果を返していました。phpMyAdminが結果を読み切らないまま自動の `SET FOREIGN_KEY_CHECKS = ON;` を実行し、`Commands out of sync` になる不具合を再現しました。`ON` を `1` に変えるだけではこの接続状態は解消しません。

**エラー表示だけを理由に再構築SQLを再実行しないでください。** phpMyAdminを開き直して対象DBを選び、[読み取り専用の確認SQL](../sake_catalog_verify.sql) を実行します。再構築直後の期待値は商品2,296件・ID1〜2296・詳細2,296件・度数1,521件・価格919件・画像URL1,914件です。登録済みなら再インポートは不要です。

現在の再構築SQLは、結果を返す処理を匿名複合文の外へ移しています。列一覧も `SHOW COLUMNS FROM sake` で表示し、phpMyAdminによる参照DBの切替を避けています。

## クライアントから初回実行する場合

```bash
mariadb --default-character-set=utf8mb4 --host=127.0.0.1 --user=DBユーザー \
  --password 対象DB名 < data/sake_catalog_rebuild.sql
```

## 再構築の内容

- 外部キーを壊さないため、親表をDROPせず、指定した10カラムの定義・順序へALTERしてから全行を再登録します。
- データ削除前に、対象7テーブルがInnoDBであること、sakeの列・FK型、既知の4つのCASCADE参照、孤児行がないことを検査します。未知の同DB/別DBからの参照や必要FKの欠落があれば、削除前に停止します。
- 2,296商品の酒蔵・酒種がすべて対応できることを確認した後、単一トランザクションで削除・再投入します。途中の例外では元の商品と連鎖削除された関連行をROLLBACKし、ロックを解放してエラーを返します。
- 列順変更DDLは削除前に実行するため、失敗時に列順だけが変わる場合はあります。データ再投入成功後のCOMMITに続き、自動採番の次値を2297へ揃えます。DDL自体はトランザクションで元に戻せません。
- 商品IDは北海道から都道府県コード順に1〜2296を明示して登録します。`created_at` は実行時の日本時間です。次の管理画面登録は2297からです。
- 数値度数1,521件、容量確認済み税込価格919件、画像URL1,914件を入れ、未確認項目と紹介文はNULLにします。診断タグは推測で作りません。
- 古い同梱紹介JSONのID1〜10を新しい北海道商品へ流用しないよう、全2,296商品の新ID・名前・酒蔵に対応する詳細JSONを作成します。確認済み価格があれば容量・税込価格も登録します。
- 写真URLを登録しても公開利用の承認状態は変えません。承認台帳はID・名前・URLの一致を確認するため、以前の承認が別商品へ自動で移ることはありません。

再実行のたびに、その時点の商品・お気に入り等を初期化し直します。空欄を埋めるだけの通常作業には [属性補完SQL](../sake_catalog_attributes.sql) を使います。

当作業環境から利用者の実DBへは接続していません。利用者からは、取り込み後の件数確認として2,296件・ID1〜2296の結果が報告されています。属性や列順の実DB確認結果はまだ受け取っていません。
