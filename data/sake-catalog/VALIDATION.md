# 日本酒追加・属性補完SQLの検証記録

実施日：2026年11月12日。商品名・酒種等は11月10〜11日の確認を保持し、属性は11〜12日に確認した。

## 収録した範囲

- 追加対象：2,296商品、130酒蔵、46都道府県。初期10商品は追加対象件数に含めない。
- 保存済みの全 `regions/*.json` を1本の `data/sake_catalog_prefecture_order.sql` に統合した。
- 新規追加は北海道から都道府県コード順。既存商品のIDは変更しない。
- 沖縄県は0件。旧製品の現行供給を確認できず、理由は `regions/41-47-exclusions.md` に記録した。
- 全国の全商品を網羅したものではない。容量・容器・受賞ラベルのみの違いは統合し、分類や商品差が不明なものは保留した。
- 各商品の確認日・公式出典・名称補記・季節商品の留意事項は `sources.csv` に記録した。調査日には2026年11月10日・11日が混在する。
- 属性出典レコードは2,056商品。数値度数1,521件、税込価格919件（うち720ml806件）、画像URL1,914件。3項目が揃うのは669商品。
- 単一数値にできない度数196件は原文だけを台帳に残し、DBの数値度数はNULLとした。未確認の項目もNULLで、紹介文・診断タグは推測で追加していない。
- 初回用SQLと、以前の版へ空欄だけを補完する属性専用SQLを生成。両方のZIP内容とSQLのバイト一致・CRCを確認した。
- 画像URLは商品写真候補であり、公開表示の承認台帳は変更していない。

## 検証環境と結果

MySQL 8.4.13とMariaDB 10.11.19の使い捨てDockerコンテナを使用。ホストのポートは公開せず、アプリの実DBには接続していない。既存の作成DDLを隔離DBへ適用してから、両DBで同じ生成SQLを検証した。

```bash
python3 scripts/build-sake-catalog.py
python3 scripts/build-sake-catalog.py --check
python3 scripts/tests/test_sake_catalog_mysql.py
python3 scripts/tests/test_sake_catalog_mysql.py --image mariadb:10.11
git diff --check
```

入力・生成物・ZIPの整合性検査と、出典検証・DB互換性を含むフルテスト全17項目が両DBで成功した。

| 検証 | 結果 |
|---|---|
| 初回追加・再実行・県順・外部キー | 2,296件追加、確認済み3属性と価格詳細が出典どおり。初期10件とタグを保持、再実行による追加0件。新規IDは県順、FKも一致 |
| 部分版から拡張版への適用 | 部分版適用後の470商品のID・識別情報・入力済み値を保持し、未登録商品と確認済み空欄だけを追加 |

新規コンテナの起動確認では、初期化用の一時サーバーを完成状態と誤認しないよう、コンテナ内部のTCP接続で最終サーバーの起動を待つ。検証終了時には専用コンテナを削除する。

互換性修正では、幅・カナ・一部互換漢字を一時表のキーで段階的に正規化した後、両DBにある `utf8mb4_bin` で全文一致を判定する。永続スキーマや実際の商品名は変更しない。対応していない特殊なUnicode表記は保守的に一致しない場合があり、曖昧な同一視による誤補完は行わない。

## 確認の限界

公式出典の再取得と、混載一覧・似た商品名・容量や箱の差・商品写真の対応を重点照合した。誤った別商品画像、広告・受賞ロゴ、NO IMAGEを訂正または除外し、容量を確認できない価格はNULLへ戻した。生成スクリプト自体は公式情報の真偽や公開利用の許諾を判定しない。

価格は720ml・税込を優先し、720mlがない場合は公式に明示された別容量を採用した。税計算や曖昧な容量別価格の最小値による補完はしていない。写真はHTTP成功だけでなく公式ページとの商品対応も確認したが、現在の在庫・将来の価格・画像URL継続を保証するものではない。

適用先のアプリ用DBには未適用で、画面・診断・商品詳細の動作を今回の追加データで確認した記録ではない。実DBへ適用する場合はREADMEの手順で接続先を選び、SQLの追加件数・既存スキップ数・保留一覧を確認する。
