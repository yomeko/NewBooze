# 日本酒追加SQLの検証記録

実施日：2026年11月11日。

## 収録した範囲

- 追加対象：2,296商品、130酒蔵、46都道府県。初期10商品は追加対象件数に含めない。
- 保存済みの全 `regions/*.json` を1本の `data/sake_catalog_prefecture_order.sql` に統合した。
- 新規追加は北海道から都道府県コード順。既存商品のIDは変更しない。
- 沖縄県は0件。旧製品の現行供給を確認できず、理由は `regions/41-47-exclusions.md` に記録した。
- 全国の全商品を網羅したものではない。容量・容器・受賞ラベルのみの違いは統合し、分類や商品差が不明なものは保留した。
- 各商品の確認日・公式出典・名称補記・季節商品の留意事項は `sources.csv` に記録した。調査日には2026年11月10日・11日が混在する。
- 追加商品の度数・価格・紹介文・画像はNULL、診断タグは未設定。未確認の数値・味わいを補っていない。

## 検証環境と結果

MySQL 8.4.13の使い捨てDockerコンテナを使用。ホストのポートは公開せず、アプリの実DBには接続していない。既存の作成DDLを隔離DBへ適用してから検証した。

```bash
python3 scripts/build-sake-catalog.py
python3 scripts/build-sake-catalog.py --check
python3 scripts/tests/test_sake_catalog_mysql.py
git diff --check
```

入力・生成物の整合性検査と、以下のMySQL統合テスト8件がすべて成功した。

| 検証 | 結果 |
|---|---|
| 初回追加・再実行・県順・外部キー | 2,296件追加、初期10件と診断タグを保持、再実行による追加0件。新規IDは県順、酒蔵・酒種FKも一致 |
| 部分版から拡張版への適用 | 部分版適用後の470商品をID・値・外部キーごと保持し、未登録商品だけを追加 |
| 空白等の表記違い | 半角・全角空白・タブを含む既存商品を二重登録せず保持 |
| 明示した別名 | 入力JSONのaliasesに一致する既存商品を二重登録せず保持 |
| 文字幅・法人表記 | 全角英数字・大小文字・半角カナを照合し、㈱・㍿等の既存酒蔵を再利用 |
| 名前付きロックを取得できない場合 | 未適用ステータスを返し、商品・酒蔵・酒種の永続テーブルを変更しない |
| 既存酒蔵の県名が異なる場合 | 対象商品を保留として表示し、既存商品・診断タグを保持 |
| 正規化すると同名の酒蔵が複数ある場合 | 酒蔵を誤って選ばず保留とし、既存商品・診断タグを保持 |

新規コンテナの起動確認では、初期化用の一時サーバーを完成状態と誤認しないよう、コンテナ内部のTCP接続で最終サーバーの起動を待つ。検証終了時には専用コンテナを削除する。

## 確認の限界

公式出典の再取得と、混載一覧の酒種・似た商品名・容量やラベル差などを重点照合した。生成スクリプト自体は公式情報の真偽を判定しない。今回の最終段階では、埼玉〜石川の追加110商品の公式商品・会社情報70 URLを再取得し、各県の根拠も確認した。

適用先のアプリ用DBには未適用で、画面・診断・商品詳細の動作を今回の追加データで確認した記録ではない。実DBへ適用する場合はREADMEの手順で接続先を選び、SQLの追加件数・既存スキップ数・保留一覧を確認する。
