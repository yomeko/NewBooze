## 台帳の項目

| 項目 | 内容 |
| --- | --- |
| `sakeId` / `sakeName` | DBの銘柄IDと銘柄名。両方の完全一致が必要 |
| `imageUrl` | 個別に確認した画像URL。クエリを含め完全一致し、他のURLや同じドメインには承認を広げない。HTTPS、または下記のローカル保存場所に限定 |
| `sourcePage` | 写真の出典となる商品ページ。これだけでは承認しない |
| `approved` | 運営者が以下の根拠と条件を確認した場合だけ `true` |
| `rightsHolder` | 公開利用を許諾する権利者名、または自分で撮影して権利を有することを確認した撮影者名 |
| `permissionSource` | 画像の公開利用を認める公式規約、ライセンス、または確認記録のHTTPS URL。出典の商品ページだけを入れて代用しない |
| `permissionCheckedOn` | 利用根拠を確認した日（`YYYY-MM-DD`）。日本時間の当日以前 |
| `usageConditions` | このサイトの目的・期間・掲載方法で利用できる範囲と、守る必要のある条件を記録 |

許諾記録にメール本文、連絡先などが含まれる場合は、公開リポジトリにその内容を載せず、アクセスを制限した記録を参照してください。公開ページへ必要なクレジット表記がある場合は、その表示を先に実装・確認してください。現在の台帳はクレジット表記を自動で画面に追加しません。期限などの条件も自動処理しないため、条件を満たせなくなった時点で承認を取り下げて再ビルド・再起動します。

ローカル写真は `/images/sake/` の英数字・`_`・`-` のファイル名（JPEG・PNG・WebP・GIF）、または管理画面が発行する `/sake/images/UUID.jpg`・`UUID.png` を使います。親ディレクトリへの移動や任意のローカルパスは許可しません。保存場所の制限と公開利用の承認は別々に確認します。

## 写真を公開する手順

1. 使用する個別の写真について、権利者・公開利用の根拠と条件を確認します。Web上に表示される写真を無断でダウンロードしたり、許諾を推測して承認したりしません。自分で撮った写真も、必要な権利・条件を確認します。
2. 台帳に銘柄ID・銘柄名・実際に使う完全な画像URLと確認情報を記録します。現在の未確認候補を単に `true` に切り替えないでください。
3. 掲載期間・加工・配信方法・クレジットなどの条件をこのサイトで満たせることを確認してから `approved: true` にします。
4. 再ビルド・再起動し、トップ・検索・診断・詳細の表示を確認します。未承認URLや別写真に承認が広がっていないことも確認します。
5. 写真URLや銘柄名を変更した場合は再確認します。許諾の失効・条件変更時は `approved: false` にして再ビルド・再起動します。

アプリは台帳を起動時に読み、承認指定に加えて銘柄ID・名前、画像URL、権利者名、HTTPSの根拠URL、正しい形式の確認日、利用条件が揃った写真だけを採用します。これは入力の確認であり、根拠文書の内容や実際の権利を自動判定する仕組みではありません。重複記録やJSONの読み込み不良は起動エラーにし、台帳を無視して全写真を表示する動作には切り替えません。

## データ保持と画面

`ProductImagePublicationService.displayUrl` を `SakeCatalogService` のDB→表示モデル変換で呼びます。ホーム・検索・診断・詳細へ渡す商品写真URLだけを制御し、DBの `sake.image_url` や写真ファイルは削除・上書きしません。管理画面での画像登録も利用根拠の確認とは別であり、台帳で個別承認するまで公開画面には表示しません。

未承認の銘柄も名前・紹介情報・検索・診断・公式サイトへのリンクは利用できます。カードは既存の「商品写真準備中」、詳細は写真欄を省略します。画像が不要になった場合も、この台帳だけを理由にDBやファイルを一括削除しません。
