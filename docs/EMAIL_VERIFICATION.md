# Gmailで確認メールを送信する

新規登録 → 仮登録 → 確認メールのリンクを開く → 登録完了 → ログインの順に進みます。
未認証ユーザーはログインできず、仮パスワードも発行しません。確認リンクは24時間有効で、一度だけ使えます。
DBに保存するのはトークンのSHA-256ハッシュだけです。再送すると以前のリンクは無効になり、再送間隔は60秒です。
メール送信に失敗した場合は登録・トークン更新をロールバックします。

## DB更新

既存DBでは、起動前に `data/email_verification_schema.sql` を一度だけ実行してください。
既存会員と管理者は認証済みとして扱います。新規DBには更新済みの作成SQLを使用します。
`ddl-auto=validate`なのでアプリは自動でDBを変更しません。

## Gmail設定

1. 送信元Googleアカウントの2段階認証を有効にします。
2. Googleアカウントの「アプリパスワード」を発行します。通常のログインパスワードは使用しません。
   組織の設定によってはアプリパスワードを利用できません。
3. 実行環境に以下の環境変数を設定してアプリを起動します。

```text
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=送信元のGmailアドレス
MAIL_PASSWORD=発行したアプリパスワード
MAIL_FROM=送信元のGmailアドレス
MAIL_SMTP_AUTH=true
MAIL_STARTTLS=true
APP_PUBLIC_BASE_URL=https://実際の公開ドメイン
```

パスワードはGitに保存しないでください。ローカルではGit対象外の `application-local.properties` に
対応するSpringプロパティを設定する方法もあります。ローカル確認時のURLは `http://localhost:8080` です。
既定のSMTPは `localhost:1025`（開発用メール受信サーバー）を維持しています。

## 動作確認

- 新しいアドレスで登録し、認証前のログインが拒否されることを確認します。
- 受信したリンクを開いて登録完了表示を確認し、ログインします。
- 同じリンクを再び開くと無効になることを確認します。
- 未認証アドレスで60秒後に再送し、古いリンクが無効になることを確認します。
- SMTP停止時は送信エラーが表示され、仮登録が残らないことを確認します。

Gmailの実送信には上記の設定とDB更新が必要です。Gmailには送信数の制限があります。
