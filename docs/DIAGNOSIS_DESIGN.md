# 分岐診断と味わい4象限の設計

確認日 2026年10月15日。日本酒初心者が日常の好みから答えられることを目的とする。心理検査として妥当性を検証した尺度ではない。

## 質問数と認知負担

共通4問に回答別の掘り下げ2問を加えて全6問とする。研究が特定の最適質問数を保証するわけではなく、負担と好みの情報量を両立させる初期設計である。選択式、1画面1問、進捗表示、戻る操作、分岐先の「どちらも好き・まだわからない」により、理解・判断・回答の負担を減らす。中立回答には加点しない。所要時間や精度の改善は未検証であり、利用者テストで完了率・所要時間・理解しづらい語・推薦への納得感を確認する。

質問の理解と認知負担については英国Government Analysis FunctionのQuestionnaire design guidance、回答に関係する質問だけを出す方針についてはGOV.UKのStructuring forms、固定の最適長がないことについてはPew Research Centerの解説を参照した。

- https://www.gov.uk/service-manual/design/form-structure
- https://www.pewresearch.org/decoded/2022/12/08/how-we-keep-our-online-surveys-from-running-too-long/

## 質問の経路

1. 共通の「気分に近い一杯」で香り・うまみ・すっきりを選択。
2. 果物の香り／うまみのある料理／すっきりした飲み物のいずれかを掘り下げ、軽快と濃醇を補足。
3. 共通の「口当たりの好み」。
4. 共通の「合わせたい場面」。
5. 共通の「甘さの印象」。
6. 甘みあり／甘さ控えめ／甘くない後味のいずれかを掘り下げ、甘口と辛口を補足。

設問バンクは10問・30選択肢だが、送信するのは6回答のみ。IDの固定値に依存せず、設問・選択肢の文言をキーに分岐条件を作るため、文言変更時はDiagnosisService.BRANCHESとSQLを同時に変更する。表示順は共通sort_order×10、追加設問は11〜13・41〜43。ブラウザとサーバーの両方で経路を判定し、経路外・重複・不足の回答は保存しない。戻って親回答を変更すると経路を外れた回答は破棄する。

## 4象限と用語解説

提供画像に合わせ、左上を濃醇甘口、右上を濃醇辛口、左下を淡麗甘口、右下を淡麗辛口とする。横軸は甘辛、縦軸は飲みごたえであり、酸度そのものではない。人口や回答の分布が各象限に均等になるような強制的な調整は行わない。

x = 50 + 40 × (辛口 − 甘口) / (辛口 + 甘口)
y = 50 + 40 × (軽快 − 濃醇) / (軽快 + 濃醇)

分母0は50、同点は境界線とし、「中間」と表示する。整数へ四捨五入する。座標は回答タグの相対値で、日本酒度・酸度の実測値や嗜好の確率ではない。推薦は引き続き全タグのコサイン類似度を使う。追加質問の加点は基本2点に抑え、既存の5点の回答を補足する。重みは設計上の仮設定で、心理測定による校正は未実施。

甘口・辛口・淡麗・濃醇・旨口・酸味・フルーティーの解説はHTML Popoverで開く。タップ、Enter、Spaceで開き、閉じるボタン、Escape、外側のクリックで閉じられる。意味は日本酒造組合中央会と酒類総合研究所の説明を参考に要約した。甘辛は糖分だけでは決まらず、酸などとのバランスによる。フルーティーは香りであり甘口と同義ではない。
