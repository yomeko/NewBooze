## 今回変更した内容

- 管理者は環境変数を明示した場合だけ作成し、旧版の固定パスワードによる管理者ログインも拒否する。
- 会員登録後の自動ログイン時にセッションIDを更新する。パスワードのBCrypt上限を文字数とUTF-8バイト数で確認する。
- 再設定メールの送信先となるメールアドレスを変更するときは、現在のパスワードによる再認証を必須にする。表示名だけの変更には要求しない。
- セッションCookieをHttpOnly・SameSite=Laxにし、URLへのセッションID埋め込みを禁止する。無操作期限を20分にする。
- CSPでスクリプトの実行元を同一サイトに制限し、外部サイトへのReferer送信を止める。CSPに合わせて画面内のJavaScriptを外部ファイルへ移した。
- 小さいプロフィール画像も再生成し、EXIF、テキストなどの付加情報を引き継がない。画像形式は実データから決定し、2000万画素を超える画像をデコード前に拒否する。GIFは先頭フレームの静止画として保存する。
- 本人画像・公開レビューの画像ともno-storeにする。エラー応答に例外、スタックトレース、バインド値を表示させない。
- 本番用設定と、秘密情報が入りやすいファイルのGit除外を追加した。Git除外は既存コミットの秘密情報を消す機能ではない。

## 公開環境への適用

1. `SPRING_PROFILES_ACTIVE=production` を指定する。DB用の `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` とSMTP用の `MAIL_HOST`、`MAIL_USERNAME`、`MAIL_PASSWORD`、`MAIL_FROM` を実行環境の秘密情報として設定する。これらは本番プロファイルでは必須で、開発用のローカル設定ファイルは読み込まない。
2. HTTPSを構成し、HTTPからHTTPSへ転送する。アプリのHTTPポートは信頼したリバースプロキシからだけ到達できるようにする。Secure Cookieだけでは、HTTPで送信されるログインフォームやパスワードは暗号化できない。
3. TLSをプロキシで終端する場合は、プロキシが転送ヘッダーを上書きし、アプリ側がそのプロキシだけを信頼するよう構成する。送信元が任意に付ける転送ヘッダーを無条件で信用しない。
4. DBは外部へ公開せず、アプリからだけ接続を許可する。rootを使わず、必要なテーブル操作だけを許可した専用ユーザーを使う。DBが別ホストなら証明書を検証するTLS接続を設定する。
5. SMTPはSTARTTLS対応サーバーを使用する。本番プロファイルではTLSを必須にし、接続先の証明書とホスト名を検証する。
6. `docs/admin.md` の手順で管理者を準備し、アプリを再起動する。HTTPS上でログイン・ログアウト・管理画面の403・写真アップロードを確認する。
7. 更新前に登録されたプロフィール写真には付加情報が残っている可能性がある。写真を削除して再アップロードするか、バックアップと復元手順を確認したうえで一括再生成する。今回の修正は既存DBの画像を自動更新しない。

## 次に優先する対策

1. 仮パスワード方式を、有効期限付き・一回だけ使用できるパスワード再設定トークンに置き換える。メールの所有確認が済むまで既存パスワードを変更しない。
2. ログイン・登録・再設定の試行回数とメール送信回数を制限する。複数台構成でも共通のカウンターを使い、成功時と失敗時の応答で登録有無を漏らさない。
3. 管理者の二段階認証、重要操作の再認証、パスワード変更・退会時の他端末のセッション失効を追加する。
4. パスワード・トークン・メール本文・個人情報をログへ出さず、認証失敗・権限エラー・管理操作を監視して異常時に通知する。
5. 依存関係の脆弱性スキャン、バックアップの暗号化・アクセス制限・復元試験、第三者による診断を実施する。

実際に認証情報が漏れた場合、コード修正に加えて該当パスワードやAPIキーの失効・変更が必要です。調査用ログは保全し、認証情報そのものは報告書やGitへ記載しないでください。

## 今回の検証

隔離したMariaDB 10.11のテストDBを新規作成し、既存の画面・ログイン・登録・レビュー・管理機能と追加したセキュリティテストの計61件が成功しました。JavaScriptテスト3件、`bootJar` の作成、`git diff --check` も成功しました。外部AI APIはテスト実行中に無効化し、本番DBへは接続していません。

追加テストでは、管理画面の認証・権限・CSRF、他ユーザーIDを指定しても本人画像だけを返すこと、メールアドレス変更の再認証、固定初期管理者の拒否、登録時のセッションID更新、小さい画像のメタデータ除去、巨大な画像寸法の拒否、セキュリティヘッダーを確認しました。既存の追跡ファイルには認識可能なAPIキー・秘密鍵パターンは見つかりませんでしたが、Git履歴や未知の形式を含む網羅的な秘密情報検査ではありません。
